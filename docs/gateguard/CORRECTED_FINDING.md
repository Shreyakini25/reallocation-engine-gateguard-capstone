# GateGuard Corrected Run Finding

## Status

CONFIRMED CORRECTION.

The role scorer was modified only after the original failing baseline and
boundary evidence had been preserved.

## Target defect

Closed-Gate Residual Score Defect.

The original scorer classified liveness or timeline factors at or below
`gate_zero = 0.05` as closed, but retained a non-zero composite when the
closed factor itself was greater than zero.

## Minimal correction

The scorer now separates:

- the raw multiplicative result; and
- the final decision composite.

The raw result is calculated as:

`multipliedComposite = voteSum * gateProduct`

The scorer then applies its existing closed-gate classification.

If a required gate is closed:

`composite = 0`

Otherwise:

`composite = multipliedComposite`

## Boundary preservation

The fix does not zero every weak gate.

For both liveness and timeline:

- `0.05` is classified closed and now returns composite `0`;
- `0.0501` remains positive;
- `0.10` remains positive;
- `1.0` remains a healthy open-gate control.

This demonstrates that the correction enforces the scorer's existing
closed-gate boundary rather than introducing a broader cutoff.

## Audit trace

The correction preserves the raw multiplication before applying the hard
stop.

Example from the corrected run:

`(0.9·0.35 + 0.9·0.3) × 0.05 × 1 = 0.029 → 0.000 (closed liveness gate)`

For maximum registered votes:

`(1·0.35 + 1·0.3) × 0.05 × 1 = 0.032 → 0.000 (closed liveness gate)`

This makes both the arithmetic and the gate intervention visible.

## Scope

This correction addresses only the confirmed Closed-Gate Residual Score
Defect.

It does not silently resolve the separately documented robustness questions
around:

- missing gate inputs;
- null gate inputs;
- non-numeric values;
- factors greater than one.

Those remain explicit robustness risks or maintainer policy questions.

## Evidence boundary

All GateGuard roles and factor values are fictional controlled inputs.

PASS/FAIL counts were generated by the committed GateGuard harness.

Composite values, recommendations, and traces came from the role scorer.

No real candidate, employer, job posting, immigration record, or private
personal data was used.
